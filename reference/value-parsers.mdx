Value parsers are the layer between raw command-line strings and the typed Rust values your application works with. Every argument has a value parser — either selected automatically by `value_parser!(T)` or set explicitly with `Arg::value_parser`. This page covers every parser clap ships, plus how to build your own.

## The `ValueParser` Type

`ValueParser` is the central type. It wraps any `TypedValueParser` implementation in a type-erased container so it can be stored and called uniformly.

```rust
use clap::{Command, Arg, builder::NonEmptyStringValueParser};

let mut cmd = Command::new("raw")
    .arg(
        Arg::new("color")
            .long("color")
            .value_parser(["always", "auto", "never"])
            .default_value("auto")
    )
    .arg(
        Arg::new("hostname")
            .long("hostname")
            .value_parser(NonEmptyStringValueParser::new())
            .action(clap::ArgAction::Set)
            .required(true)
    )
    .arg(
        Arg::new("port")
            .long("port")
            .value_parser(clap::value_parser!(u16).range(3000..))
            .action(clap::ArgAction::Set)
            .required(true)
    );
```

## Built-in Parsers

### `StringValueParser`

Parses to `String`. Fails on non-UTF-8 input. This is the default for most string arguments.

```rust
use clap::{Command, Arg};

let mut cmd = Command::new("raw")
    .arg(
        Arg::new("port")
            .value_parser(clap::value_parser!(String))
            .required(true)
    );

let m = cmd.try_get_matches_from_mut(["cmd", "80"]).unwrap();
let port: &String = m.get_one("port").expect("required");
assert_eq!(port, "80");
```

### `OsStringValueParser`

Parses to `OsString`. Accepts any byte sequence, including non-UTF-8. Useful on Unix for paths with arbitrary encodings.

```rust
use clap::{Command, Arg, builder::ValueParser};

let r = Command::new("myprog")
    .arg(
        Arg::new("arg")
            .required(true)
            .value_parser(ValueParser::os_string())
    );
```

### `PathBufValueParser`

Parses to `PathBuf`. Rejects empty strings (unlike `OsStringValueParser`).

```rust
use clap::{Command, Arg};
use std::path::PathBuf;

let mut cmd = Command::new("raw")
    .arg(
        Arg::new("output")
            .value_parser(clap::value_parser!(PathBuf))
            .required(true)
    );

let m = cmd.try_get_matches_from_mut(["cmd", "hello.txt"]).unwrap();
let port: &PathBuf = m.get_one("output").expect("required");
assert_eq!(port, std::path::Path::new("hello.txt"));

assert!(cmd.try_get_matches_from_mut(["cmd", ""]).is_err());
```

### `BoolValueParser`

Parses the strings `"true"` and `"false"` to `bool`. Any other value is rejected.

```rust
let mut cmd = clap::Command::new("raw")
    .arg(
        clap::Arg::new("download")
            .value_parser(clap::value_parser!(bool))
            .required(true)
    );

let m = cmd.try_get_matches_from_mut(["cmd", "true"]).unwrap();
let val: bool = *m.get_one("download").expect("required");
assert_eq!(val, true);

assert!(cmd.try_get_matches_from_mut(["cmd", "forever"]).is_err());
```

### `BoolishValueParser`

A more human-friendly boolean parser that accepts a wider set of truthy and falsy strings. Use this instead of `BoolValueParser` when accepting end-user configuration values.

```rust
use clap::builder::BoolishValueParser;
```

<Tip>
  Use `BoolishValueParser` for environment variables and config-file style
  inputs. Use `BoolValueParser` (or the bare `bool` type) when you need strict
  `true`/`false` string parsing.
</Tip>

### `NonEmptyStringValueParser`

Parses to `String` but rejects empty strings with an error. Drop-in replacement for `StringValueParser` when an empty value would be meaningless.

```rust
use clap::{Command, Arg, builder::NonEmptyStringValueParser};

let mut cmd = Command::new("raw")
    .arg(
        Arg::new("hostname")
            .long("hostname")
            .value_parser(NonEmptyStringValueParser::new())
            .action(clap::ArgAction::Set)
            .required(true)
    );

let m = cmd.try_get_matches_from_mut(
    ["cmd", "--hostname", "rust-lang.org"]
).unwrap();

let hostname: &String = m.get_one("hostname").expect("required");
assert_eq!(hostname, "rust-lang.org");
```

## Ranged Numeric Parsers

### `RangedI64ValueParser<T>`

Parses a signed integer and validates it lies within an optional range. The output type `T` can be any type that implements `TryFrom<i64>` — so you can produce `i8`, `i16`, `i32`, `i64`, etc.

```rust
use clap::{Command, Arg};

let mut cmd = Command::new("raw")
    .arg(
        Arg::new("port")
            .long("port")
            .value_parser(clap::value_parser!(u16).range(3000..))
            .action(clap::ArgAction::Set)
            .required(true)
    );

let m = cmd.try_get_matches_from_mut(["cmd", "--port", "3001"]).unwrap();
let port: u16 = *m.get_one("port").expect("required");
assert_eq!(port, 3001);
```

Range forms that are accepted:

| Rust Syntax | Meaning |
|---|---|
| `3000..4000` | Exclusive end: 3000 ≤ n < 4000 |
| `3000..=4000` | Inclusive end: 3000 ≤ n ≤ 4000 |
| `3000..` | Lower bound only |
| `..3000` | Upper bound (exclusive) only |
| `..=3000` | Upper bound (inclusive) only |
| `..` | Full `i64` range |

Semantics example:

```rust
use clap::builder::{RangedI64ValueParser, TypedValueParser};
use std::ffi::OsStr;
let cmd = clap::Command::new("test");
let arg = None;

let value_parser = RangedI64ValueParser::<i32>::new().range(-1..200);
assert!(value_parser.parse_ref(&cmd, arg, OsStr::new("random")).is_err());
assert!(value_parser.parse_ref(&cmd, arg, OsStr::new("")).is_err());
assert!(value_parser.parse_ref(&cmd, arg, OsStr::new("-200")).is_err());
assert!(value_parser.parse_ref(&cmd, arg, OsStr::new("300")).is_err());
assert_eq!(value_parser.parse_ref(&cmd, arg, OsStr::new("-1")).unwrap(), -1);
assert_eq!(value_parser.parse_ref(&cmd, arg, OsStr::new("50")).unwrap(), 50);
```

<Warning>
  To accept negative numeric values on the command line, you must also set
  `Arg::allow_negative_numbers` or `Arg::allow_hyphen_values`.
</Warning>

### `RangedU64ValueParser<T>`

The unsigned equivalent. Output type `T` must implement `TryFrom<u64>`.

```rust
use clap::{Command, Arg};

let mut cmd = Command::new("raw")
    .arg(
        Arg::new("port")
            .long("port")
            .value_parser(clap::value_parser!(u64).range(3000..))
            .action(clap::ArgAction::Set)
            .required(true)
    );

let m = cmd.try_get_matches_from_mut(["cmd", "--port", "3001"]).unwrap();
let port: u64 = *m.get_one("port").expect("required");
assert_eq!(port, 3001);
```

## Enum Parsers

### `EnumValueParser<E>`

Parses a value into a type implementing `ValueEnum`. Automatically provides possible values for help text and shell completions.

```rust
use clap::{Command, Arg, ColorChoice, builder::EnumValueParser};

let mut cmd = Command::new("raw")
    .arg(
        Arg::new("color")
            .value_parser(EnumValueParser::<ColorChoice>::new())
            .required(true)
    );

let m = cmd.try_get_matches_from_mut(["cmd", "always"]).unwrap();
let color: ColorChoice = *m.get_one("color").expect("required");
assert_eq!(color, ColorChoice::Always);
```

Semantics:

```rust
use clap::{ColorChoice, builder::{EnumValueParser, TypedValueParser}};
use std::ffi::OsStr;
let cmd = clap::Command::new("test");
let arg = None;

let value_parser = EnumValueParser::<ColorChoice>::new();
assert!(value_parser.parse_ref(&cmd, arg, OsStr::new("random")).is_err());
assert_eq!(value_parser.parse_ref(&cmd, arg, OsStr::new("always")).unwrap(), ColorChoice::Always);
assert_eq!(value_parser.parse_ref(&cmd, arg, OsStr::new("auto")).unwrap(), ColorChoice::Auto);
assert_eq!(value_parser.parse_ref(&cmd, arg, OsStr::new("never")).unwrap(), ColorChoice::Never);
```

### `PossibleValuesParser`

Validates that the input string is one of a fixed set of values. Parses to `String`. Useful when you do not have a `ValueEnum` type (e.g., for dynamically computed possible values).

```rust
use clap::{Command, Arg, builder::PossibleValuesParser};

let mut cmd = Command::new("raw")
    .arg(
        Arg::new("color")
            .value_parser(PossibleValuesParser::new(["always", "auto", "never"]))
            .required(true)
    );

let m = cmd.try_get_matches_from_mut(["cmd", "always"]).unwrap();
let color: &String = m.get_one("color").expect("required");
assert_eq!(color, "always");
```

You can also pass an array literal directly to `value_parser`, which creates a `PossibleValuesParser` implicitly:

```rust
use clap::{arg, command};

fn main() {
    let matches = command!()
        .arg(
            arg!(<MODE>)
                .help("What mode to run the program in")
                .value_parser(["fast", "slow"]),
        )
        .get_matches();

    match matches
        .get_one::<String>("MODE")
        .expect("'MODE' is required and parsing will fail if its missing")
        .as_str()
    {
        "fast" => { println!("Hare"); }
        "slow" => { println!("Tortoise"); }
        _ => unreachable!(),
    }
}
```

## The `value_parser!` Macro

The `value_parser!(T)` macro automatically selects the appropriate `ValueParser` for a given type. It is used by the derive macro and is available for manual use.

<Tabs>
  <Tab title="Derive API">
    ```rust
    use clap::Parser;

    #[derive(Parser)]
    #[command(version, about, long_about = None)]
    struct Cli {
        /// Network port to use
        #[arg(value_parser = clap::value_parser!(u16).range(1..))]
        port: u16,
    }

    fn main() {
        let cli = Cli::parse();
        println!("PORT = {}", cli.port);
    }
    ```
  </Tab>
  <Tab title="Builder API">
    ```rust
    use clap::{arg, command, value_parser};

    fn main() {
        let matches = command!()
            .arg(
                arg!(<PORT>)
                    .help("Network port to use")
                    .value_parser(value_parser!(u16).range(1..)),
            )
            .get_matches();

        let port: u16 = *matches
            .get_one::<u16>("PORT")
            .expect("'PORT' is required and parsing will fail if its missing");
        println!("PORT = {port}");
    }
    ```
  </Tab>
</Tabs>

**Supported types for `value_parser!`** (auto-registered via `ValueParserFactory`):

`bool`, `String`, `OsString`, `PathBuf`, `u8`, `u16`, `u32`, `u64`, `usize`, `i8`, `i16`, `i32`, `i64`, `isize`, `Saturating<T>`, and any type implementing `ValueEnum`.

## Implementing `TypedValueParser` for Custom Types

For full control, implement the `TypedValueParser` trait directly. Your implementation must be `Clone + Send + Sync + 'static`.

```rust
use clap::error::{ErrorKind, ContextKind, ContextValue};

#[derive(Clone)]
struct Custom(u32);

#[derive(Clone)]
struct CustomValueParser;

impl clap::builder::TypedValueParser for CustomValueParser {
    type Value = Custom;

    fn parse_ref(
        &self,
        cmd: &clap::Command,
        arg: Option<&clap::Arg>,
        value: &std::ffi::OsStr,
    ) -> Result<Self::Value, clap::Error> {
        let inner = clap::value_parser!(u32);
        let val = inner.parse_ref(cmd, arg, value)?;

        const INVALID_VALUE: u32 = 10;
        if val == INVALID_VALUE {
            let mut err = clap::Error::new(ErrorKind::ValueValidation)
                .with_cmd(cmd);
            if let Some(arg) = arg {
                err.insert(ContextKind::InvalidArg, ContextValue::String(arg.to_string()));
            }
            err.insert(ContextKind::InvalidValue, ContextValue::String(INVALID_VALUE.to_string()));
            return Err(err);
        }

        Ok(Custom(val))
    }
}
```

Simpler parsers can use a bare `Fn(&str) -> Result<T, E>`, which automatically implements `TypedValueParser`:

```rust
type EnvVar = (String, Option<String>);

fn parse_env_var(env: &str) -> Result<EnvVar, std::io::Error> {
    if let Some((var, value)) = env.split_once('=') {
        Ok((var.to_owned(), Some(value.to_owned())))
    } else {
        Ok((env.to_owned(), None))
    }
}

let mut cmd = clap::Command::new("raw")
    .arg(
        clap::Arg::new("env")
            .value_parser(clap::builder::ValueParser::new(parse_env_var))
            .required(true)
    );
```

## `MapValueParser` and `TryMapValueParser`

These adapters transform the output of any existing `TypedValueParser` into a different type, allowing parser composition without writing a new struct.

### `map` — Infallible transformation

```rust
use clap::{Command, Arg, builder::{TypedValueParser as _, BoolishValueParser}};

let cmd = Command::new("mycmd")
    .arg(
        Arg::new("flag")
            .long("flag")
            .action(clap::ArgAction::SetTrue)
            .value_parser(
                BoolishValueParser::new()
                .map(|b| -> usize {
                    if b { 10 } else { 5 }
                })
            )
    );

let matches = cmd.clone().try_get_matches_from(["mycmd", "--flag"]).unwrap();
assert_eq!(matches.get_one::<usize>("flag").copied(), Some(10));

let matches = cmd.try_get_matches_from(["mycmd"]).unwrap();
assert_eq!(matches.get_one::<usize>("flag").copied(), Some(5));
```

### `try_map` — Fallible transformation

```rust
use clap::{Command, Arg, builder::{TypedValueParser as _, OsStringValueParser}};
use std::ffi::{OsString, OsStr};
use std::path::PathBuf;

fn verify_ext(os: OsString) -> Result<PathBuf, &'static str> {
    let path = PathBuf::from(os);
    if path.extension() != Some(OsStr::new("rs")) {
        return Err("only Rust files are supported");
    }
    Ok(path)
}

let cmd = Command::new("mycmd")
    .arg(
        Arg::new("flag")
            .long("flag")
            .value_parser(
                OsStringValueParser::new()
                .try_map(verify_ext)
            )
    );

let error = cmd.clone().try_get_matches_from(["mycmd", "--flag", "foo.txt"]).unwrap_err();
error.print();

let matches = cmd.try_get_matches_from(["mycmd", "--flag", "foo.rs"]).unwrap();
assert_eq!(
    matches.get_one::<PathBuf>("flag").map(|s| s.as_path()),
    Some(std::path::Path::new("foo.rs"))
);
```

## Using `ValueEnum` with Derive

The `ValueEnum` derive macro generates `EnumValueParser` behavior automatically. Variants are converted to kebab-case by default.

```rust
use clap::{Parser, ValueEnum};

#[derive(Parser)]
#[command(version, about, long_about = None)]
struct Cli {
    /// What mode to run the program in
    #[arg(value_enum)]
    mode: Mode,
}

#[derive(Copy, Clone, PartialEq, Eq, PartialOrd, Ord, ValueEnum)]
enum Mode {
    /// Run swiftly
    Fast,
    /// Crawl slowly but steadily
    ///
    /// This paragraph is ignored because there is no long help text for possible values.
    Slow,
}

fn main() {
    let cli = Cli::parse();

    match cli.mode {
        Mode::Fast => { println!("Hare"); }
        Mode::Slow => { println!("Tortoise"); }
    }
}
```

<Note>
  The doc comment summary is used as the `PossibleValue::help` text. The
  extended description (after a blank line) is currently ignored for possible
  values (as noted in the example above).
</Note>
